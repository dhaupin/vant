Persistent memory for AI agents

Every session starts over. Except yours.

Vant gives any AI agent a brain: markdown memory files in your own repository. Read when a session opens, written before it closes, inherited every time after. Git history becomes the memory lineage. No database, no lock-in, readable with cat. Start with one agent on your laptop — scale the same files up to a crew, then to installs talking across the network. Whether you are the one typing the commands or the one executing them, welcome.

The 5 minute path

Clone, start, meet your brain. No account, no cloud to configure.

$ git clone https://github.com/dhaupin/vant.git && cd vant
$ npm ci
$ vant start
$ vant onboard

01

The rhythm is yours

Three moves, at whatever pace suits: every session, once a week, or only when something is worth keeping. Vant suggests a cadence, it never demands one.

Open the brain

A session begins by reading what earlier sessions left behind: identity, goals, lessons, errors. Whoever starts next arrives already knowing things.

$ vant start
$ vant onboard wake

Work with memory

Learn facts as they happen. Search the corpus when context is missing instead of guessing.

$ vant learn deploy-gotcha "Freeze deploys during migration."
$ vant search "migration rollback steps"

Keep what matters

Write lessons back, commit, push. Plain files in your repo, so the next session starts with everything. Skip a session and nothing breaks: the memory is files, it waits.

$ git add models/ && git commit -m "agent: session learnings"
$ git push
02

Five minutes to a first win

No dashboard to configure, no account to make. The CLI is the product and the memory is files, so the first session can be this short.

Install and start

One clone, one install. vant start checks the brain layout and runs health checks before it hands over.

$ git clone https://github.com/dhaupin/vant.git && cd vant && npm ci
$ vant start

Meet the brain

It is just markdown. Read it, edit it, keep your own notes in it. vant onboard walks the files for you.

$ vant onboard
$ cat models/public/vant/identity.md

Write the first lesson

From here it just repeats: learn during the session, commit what is worth keeping, and the next session starts knowing it.

$ vant learn first-lesson "Vant works."
$ git add models/ && git commit -m "first lesson"

05

Git is the feature

Your memory is files in your repo, so every Git workflow is a memory workflow.

Ownership

Your repo, your history, your backup story. Stop using Vant and the memory survives as files. Exportable forever.

Review

What your agent learned shows up in diffs. Approve lessons in a pull request, revert the bad ones, blame the file to find where a habit started.

Branches

One branch per agent. Each works in isolation and merges what is worth keeping. Experiments are branches, not forks of your data.

08

The enterprise mesh, already in the box

This is not a roadmap slide. The distributed pieces ship today, with security and failure modes designed the same as the local ones.

Relay network

Installs expose a gated relay surface: hop-by-hop authorization with timing-safe keys, bodies as encrypted envelopes. No key, no surface — fail-closed by construction.

Relay ops →

Encrypted carriers

Memory travels as sealed stones — encrypted packets that ride images and files between installs, signatures verified on arrival. Whole brains included.

Carrier transport →

Federation playbooks

Consensus for shared decisions, settlement for the ledger, era bookkeeping for org lifecycles. The written runbooks for running several installs as one org.

Federation →

Fail-closed security chain

Sandbox capabilities, input validation, rate limiting, escrow approval on every brain operation. Refusals come back as typed codes — never silent half-writes.

Security →

Crash-safe storage

A write-ahead journal with atomic writes: a crash mid-write leaves a recoverable journal, never torn memory. Locks are cross-process, so two agents never double-write.

Storage →

Audit and access

Every operation leaves a ledger trail. Multi-guest auth with role-scoped access, row-level policies for shared state, and succession trust levels for what each generation may do alone.

11

Where Vant fits

Saying what Vant is not, because your time matters more than our conversion rate.

A strong fit when

  • You run coding agents and want session continuity without a hosted service
  • You want to review what your agent learned in a diff before it sticks
  • You are building an agent crew that needs a separate memory per agent
  • You want memory in CI: read or write brain state over REST

Not the tool yet when

  • Your agent is browser-only, with no filesystem or git access
  • Your project lives outside git (local mode works, but there is no lineage or sync)
  • You need large-scale vector serving; search is local-first, not a hosted vector database

Questions agents actually ask

The same questions your agent will ask on its first session, answered.

What is a brain in Vant?

A set of markdown files in models/ that store identity, goals, lessons, errors, and preferences. The agent reads them when a session starts and writes what it learned before it ends. The next session inherits everything.

Learn more →
Where does the memory live?

In your own repository, as plain files. Vant never puts your memory in someone else's database. If you stop using Vant, the memory is still there, readable with cat.

Do I need GitHub?

A Git host is needed for sync, and any provider works: GitHub, GitLab, Bitbucket, or self-hosted. Without sync, Vant still runs fully on local files.

Learn more →
Is my brain private?

Yes. Use a private repository and only you and the agents you authorize can access it. There is no external service holding a copy.

How do agents connect?

Through MCP: start the server with vant mcp and it auto-wires the module surface into JSON-RPC tools. Agents can also use the CLI, the REST API, or read the brain files directly.

Learn more →
Can multiple agents share one install?

Yes. Each agent gets a branch and a named brain context, so concurrent work stays isolated and shared memory merges by pull request.

Learn more →
Can I run Vant across several machines?

Yes. Multiple installs connect through gated relay surfaces, and encrypted carriers hand memory between them. Federation playbooks cover the multi-install topologies, from two pods to a full org.

Learn more →
What stops an agent from writing bad lessons?

Lessons land in git, so they arrive as reviewable diffs and revert like any file. Succession trust levels decide how much each agent generation may do unattended.

Learn more →
How safe is it to run unattended?

Every memory operation passes a security chain - sandbox capabilities, input validation, rate limiting, escrow approval - and failures refuse with typed codes instead of half-writing state. Storage is write-ahead journaled and atomic.

Learn more →
Is there a GUI?

Yes. The Brain dashboard at brain.creadev.org is a browser window into a running install: sessions, agent rosters, carrier packets, budgets, ledgers, decisions. The CLI and the REST API stay first-class for headless and CI use.

Open the dashboard →
Does Vant cost money?

No. Vant is open source under MIT. You need a Git host account and, if you want hosted embeddings, your own API key. The default hash provider needs nothing.

How is Vant different from a vector database?

A vector store keeps embeddings. Vant keeps the full context: the actual markdown, identity, goals, and lessons, with search on top. Agents inherit previous thoughts, not just similar ones.
